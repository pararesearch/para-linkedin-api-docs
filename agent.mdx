# PARA integration

PARA finds relevant LinkedIn and Reddit posts, evaluates them, optionally
generates response drafts, and makes ready drafts available for review. A
reviewed item can then be confirmed into a durable publishing queue and executed
later by the assigned browser extension.

```text
Configure -> collect -> process -> generate -> review -> confirm -> queue -> publish
```

## The important distinction

PARA has two different queue stages:

| Stage | How it starts | Platform side effect |
| --- | --- | --- |
| Human-review queue | A generated draft reaches `READY` and appears automatically | None |
| Publishing queue | A reviewer edits or accepts the draft and explicitly selects `Confirm to send` | The assigned extension may publish it later |

No API call is required to add a `READY` draft to human review. The system
automates review intake, not the review decision. Automating review decisions is
a separate capability and is not part of this flow.

Generation never posts by itself. Confirmation snapshots the final reviewed
text, destination, source metadata, project, profile, and confirming user into a
durable database queue. A server restart does not remove that item.

## Three control surfaces

| Surface | Base path | Credential | Use it for |
| --- | --- | --- | --- |
| Public API | `https://para-linkedin-api.onrender.com/v1/*` | Owner-scoped `PARA_API_KEY` | Registrations, discovery runs, results, batches, and webhooks |
| Dashboard API | `https://para-linkedin-scraper.onrender.com/api/*` | Dashboard access token | Projects, review, confirmation, posting profiles, and queue status |
| Extension API | `/api/extensions/*` | Paired device token | Collection and execution of already-approved queue items |

These credentials are not interchangeable. In particular, `PARA_API_KEY`
cannot confirm a publishing item, and dashboard credentials cannot claim an
extension task.

## Choose the operation

| Goal | Operation | Done when |
| --- | --- | --- |
| Check service readiness | `GET /health/ready` on the public API | Response has `ok: true` |
| List or configure topics | `/v1/{platform}/registrations` | Registration is reconciled by exact `external_id` |
| Start discovery | `POST /v1/{platform}/registrations/{id}/run` | The requested run or cycle is queued |
| Read final results | Batch polling or signed webhook | Immutable batch is available; `posts: []` is valid |
| Review a draft | Dashboard post or draft view | A human has accepted, edited, or rejected it |
| Confirm a LinkedIn comment | `POST /api/linkedin/comment-queue` | Response item is `QUEUED` |
| Confirm a Reddit comment | `POST /api/reddit/comment-queue` | Response item is `QUEUED` |
| Confirm a Reddit post | `POST /api/reddit/post-queue` | Response item is `QUEUED` |
| Observe publishing | LinkedIn queue or Reddit participation workspace | Item reaches `POSTED`, `FAILED`, or `CANCELLED` |

## Research flow

### 1. Authenticate

Send the public API key only through the authorization header:

```http
Authorization: Bearer ${PARA_API_KEY}
X-Request-ID: <stable-request-id>
Idempotency-Key: <stable-key-for-this-mutation>
Content-Type: application/json
```

Use `Idempotency-Key` only on mutations that declare it in
[OpenAPI](https://para-linkedin-api.onrender.com/openapi.json). Reuse the same key
only when retrying the identical operation.

### 2. Reconcile before creating

List registrations and match the operator-supplied `external_id` exactly:

```text
GET  /v1/linkedin/registrations?limit=100
GET  /v1/reddit/registrations?limit=100
POST /v1/{platform}/registrations
GET  /v1/{platform}/registrations/{id}
PATCH /v1/{platform}/registrations/{id}
```

Do not select a registration by a similar display name. Create or patch only
when the handoff authorizes that mutation.

### 3. Activate and run

```text
POST /v1/{platform}/registrations/{id}/activate
POST /v1/{platform}/registrations/{id}/pause
POST /v1/{platform}/registrations/{id}/restore
POST /v1/{platform}/registrations/{id}/run
GET  /v1/{platform}/registrations/{id}/status
```

LinkedIn `use_case` creation compiles a plan of exactly ten searches and may
auto-activate after plan and webhook validation. Poll until
`compilation_status=READY`; inspect `GET /v1/linkedin/registrations/{id}/plan`;
then wait for all requested extension runs to become terminal.

Reddit creation stores configuration without starting collection. Activation
requires at least one topic and a public HTTPS webhook. A run is then collected
through the assigned discovery extension.

### 4. Consume results

```text
GET /v1/{platform}/registrations/{id}/batches
GET /v1/{platform}/registrations/{id}/batches/{batchId}
GET /v1/{platform}/registrations/{id}/deliveries
GET /v1/reddit/registrations/{id}/posts
GET /v1/reddit/registrations/{id}/posts/{postId}
```

Results contain collected content, provenance, relevance evidence, and optional
drafts. Webhook events are `linkedin.relevant_posts.daily.v1` and
`reddit.relevant_posts.daily.v1`. Verify `X-Webhook-Signature` against
`timestamp + "." + raw_body`, deduplicate by `X-Webhook-Id`, and persist the raw
body before returning `2xx`.

## Review and publishing flow

### 1. Authenticate to the dashboard

```http
POST https://para-linkedin-scraper.onrender.com/api/auth/login
Content-Type: application/json

{"email":"operator@example.com","password":"<dashboard-password>"}
```

Use the returned `access_token` as `Authorization: Bearer
<dashboard-access-token>`. If `mustChangePassword` is true, complete
`POST /api/auth/change-password` first. Use `POST /api/auth/refresh` with the
returned refresh token when needed.

### 2. Resolve project scope

```text
GET /api/workspaces
GET /api/workspaces/{workspaceId}/projects
GET /api/projects/{projectId}
GET /api/workspaces/{workspaceId}/connections
```

Append `?projectId={projectId}` to LinkedIn and Reddit dashboard operations.
Publishing requires an active project, a source post owned by its registration,
and the correct posting or participation profile assignment.

### 3. Confirm the reviewed content

LinkedIn comment:

```http
POST /api/linkedin/comment-queue?projectId={projectId}
Authorization: Bearer <dashboard-access-token>
Content-Type: application/json

{"postId":"<dashboard-post-id>","commentText":"<final-reviewed-comment>"}
```

The response is `202` with `{item}`. A valid `READY` source draft, configured
posting identity, active posting profile, and project assignment are required.
Inspect setup and queue state with:

```text
GET  /api/linkedin/posting-profile?projectId={projectId}
GET  /api/linkedin/comment-queue?projectId={projectId}&limit=100
POST /api/linkedin/comment-queue/{itemId}/cancel?projectId={projectId}
```

Reddit comment:

```http
POST /api/reddit/comment-queue?projectId={projectId}
Authorization: Bearer <dashboard-access-token>
Content-Type: application/json

{"profileId":"<participation-profile-id>","postId":"<dashboard-post-id>","commentText":"<final-reviewed-comment>"}
```

Reddit post:

```http
POST /api/reddit/post-queue?projectId={projectId}
Authorization: Bearer <dashboard-access-token>
Content-Type: application/json

{"profileId":"<participation-profile-id>","subreddit":"example","title":"<reviewed-title>","body":"<reviewed-body>","rulesAcknowledged":true}
```

Both return `201` with `{item}`. Inspect the assigned profile, device, limits,
communities, and queues with
`GET /api/reddit/participation?projectId={projectId}`.

An explicitly reviewed Reddit vote uses:

```http
POST /api/reddit/vote-review?projectId={projectId}
Authorization: Bearer <dashboard-access-token>
Content-Type: application/json

{"profileId":"<participation-profile-id>","postId":"<dashboard-post-id>","decision":"APPROVED"}
```

Use `decision: "REJECTED"` to record that no vote should be queued.

### 4. Wait for a terminal publishing state

| State | Meaning |
| --- | --- |
| `QUEUED` | Durable item accepted; not yet posted |
| `CLAIMED` | Assigned extension holds a temporary lease |
| `RETRY_WAIT` | Retryable failure; server will make it eligible later |
| `POSTED` | Platform action completed |
| `FAILED` | Terminal failure; inspect the failure reason |
| `CANCELLED` | Pending item was cancelled |

Expired leases are recovered by the server. Regenerating the source draft does
not change the confirmed snapshot. Only `QUEUED` and `RETRY_WAIT` items can be
cancelled.

## Extension responsibilities

- The discovery extension collects page data and never claims LinkedIn posting
  tasks.
- The separate LinkedIn posting extension claims one approved comment at a time
  from the configured LinkedIn identity.
- Reddit participation is executed only through its assigned paired extension.
- Extension endpoints require device tokens and are not orchestration endpoints.
- Login, captcha, identity mismatch, restriction, or unavailable commenting may
  pause or fail publishing and must be surfaced through queue state.

## Completion rules

- A run response means work was queued, not collected.
- A `READY` draft means review is available, not approved.
- A `QUEUED` publishing item means approval was recorded, not posted.
- Only `POSTED` means the platform action completed.
- With only `PARA_API_KEY`, stop after research results and drafts are available;
  dashboard authentication and explicit approval are required to publish.

For exact public schemas, request bodies, responses, and status codes, use the
[live OpenAPI contract](https://para-linkedin-api.onrender.com/openapi.json).
