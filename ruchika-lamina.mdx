## Mutations and approvals

Read-only health, registration, plan, status, post, batch, and delivery inspection is allowed when the operator provides the owner-scoped key.

Every mutation requires a matching operator request. Use a stable `Idempotency-Key` exactly where OpenAPI declares it. In particular:

- do not patch topics, queries, thresholds, cadence, or webhook destinations merely because a different value seems preferable;
- do not activate, pause, restore, or request another run without matching task authorization;
- do not archive, rotate a webhook secret, replay delivery, or manage API keys without explicit approval for that exact action;
- do not enqueue or submit comments, posts, votes, or joins through browser automation under this handoff.

The temporary smoke receiver is validation infrastructure. A real public HTTPS webhook URL must be supplied by the operator before production delivery is considered complete.
