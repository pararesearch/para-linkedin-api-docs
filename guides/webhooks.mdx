The daily event is `linkedin.relevant_posts.daily.v1`. It is sent only after the final stored batch is ready.

## Headers

| Header | Meaning |
| --- | --- |
| `X-Webhook-Id` | Stable event UUID |
| `X-Webhook-Timestamp` | Unix timestamp in seconds |
| `X-Webhook-Signature` | `v1=` plus the HMAC-SHA256 hex digest |
| `Idempotency-Key` | Same stable event UUID |
| `X-Request-ID` | Correlation ID inherited from the source run |

Compute the expected digest over:

```text
timestamp + "." + raw_request_body
```

Always verify the raw bytes before parsing JSON. Compare digests in constant time and reject stale timestamps according to your tolerance.

```python
import hashlib
import hmac


def verify_webhook(raw_body: bytes, timestamp: str, signature: str, secret: str) -> bool:
    signed = timestamp.encode() + b"." + raw_body
    expected = "v1=" + hmac.new(
        secret.encode(),
        signed,
        hashlib.sha256,
    ).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## Retries and replay

Any `2xx` succeeds. Failed delivery retries after 1 minute, 5 minutes, 30 minutes, 2 hours, 6 hours, and 24 hours. A bounded `Retry-After` value can move the next attempt within the 1-second to 24-hour range. Requests time out after 10 seconds in production.

After retries are exhausted, the delivery is `DEAD_LETTER`. Inspect its attempt rows and call the replay endpoint with a new idempotency key after correcting the receiver.

Webhook URLs must use HTTPS. URL validation blocks private, loopback, link-local, reserved, multicast, and credential-bearing destinations, and validates every redirect target.
