FastAPI writes JSON through structlog. TypeScript writes JSON through Pino. PostgreSQL also retains run events and webhook attempts so operational evidence survives process log retention.

## Required stages

```text
api.request
registration.created
plan.compilation.queued
plan.compilation.started
plan.compilation.completed
plan.activated
task.queued
extension.claimed
posts.persisted
match.initial.completed
parallel.enrichment.completed
rerank.completed
draft.completed
batch.ready
webhook.attempt
webhook.delivered
webhook.dead_letter
```

Common fields include service, environment, event, request ID, owner, registration, requirement, task, run, batch, delivery, duration, attempt, counts, outcome, and error code.

Compiled LinkedIn events also carry plan ID, plan revision, topic ID, cycle ID,
and requirement revision. The verifier requires exactly ten `task.queued`
events for each accepted compiled cycle and requires every extension,
matching, enrichment, draft, batch, and webhook stage to remain traceable to
that cycle.

`X-Request-ID` is accepted at the public API and propagated through FastAPI, the private TypeScript request, queued run, extension claim and upload, result batch, webhook attempt, callback header, and payload.

## Redaction rules

Logs must never contain:

- API keys or raw authorization headers
- temporary passwords
- webhook plaintext secrets
- full post bodies
- raw Parallel or OpenAI responses
- raw use cases, generated prompts, or complete public profile snapshots

The E2E log verifier scans all captured logs for known fixture secrets and post-body markers, and fails when an expected stage lacks its correlation fields.

## Health

- `GET /health/live` checks the FastAPI process.
- `GET /health/ready` calls the private TypeScript readiness endpoint.
- `GET /api/health/ready` checks the TypeScript service and database.
- The private readiness endpoint verifies registration and plan migrations,
  compiler-worker configuration, OpenAI compiler configuration, and database
  connectivity.
